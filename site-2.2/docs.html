Documentation

Everything 2.2 promises, precisely stated. Nothing here redesigns the language — it pins down behavior.

1. UI coordinate system

  • x = pixels from the left edge of the parent content area.
  • y = pixels from the top edge of the parent content area.
  • Direct children of a window use the window's client area (below the title bar).
  • Children of a container are relative to that container: screen = parent + child.
  • right = x + width, bottom = y + height. Never cumulative across siblings.
button.x = 100
button.width = 80
rem left is 100, right is 180

panel.x = 50
panel.y = 50
button.x = 20
button.y = 20
rem on screen: x 70, y 70

DPI

Vexel coordinates → UI coordinate system → one DPI conversion → native pixels. Never scaled twice. Tested at 100%, 125%, 150%, 200%.

Priority

Explicit x/y > explicit size > explicit anchoring > explicit container layout > backend defaults. An explicit position is never overridden silently.

2. Containers and clipping

Manual positioning is the default. Layout only happens inside containers you create: panel, vertical/horizontal containers, grid, scroll area, form.

panel = add a panel
panel.x = 20
panel.y = 20
panel.width = 200
panel.height = 200

Children that overflow a panel are clipped (or scrollable in a scroll area) — never silently repositioned.

3. Multiple windows

main = create a window titled "Main"
settings = create a window titled "Settings"

main.width = 600
main.height = 400
settings.width = 400
settings.height = 300

main.show
settings.show

Each window has its own controls, events, dimensions, position, visibility, and lifecycle. Methods: show, hide, close, minimize, maximize, restore. Events: close, resize, move, focus, blur.

window.on resize {
    print "Window resized"
}

4. Events

The event object exposes x, y, button, key, value, target — validated per event type (keyboard events carry key, mouse events carry x/y/button).

input.on key press {
    print event.key
}

Mouse coordinates use the Vexel UI coordinate system. Removing a control (remove button) disconnects its handlers, drops its registry id, and frees its resources.

5. Tasks and timers

task load_data {
    data = http get "https://example.com/data"
}

Task states: pending, running, completed, failed, cancelled. Failures arrive as normal error objects — never silently dropped. task.cancel is cooperative: cancelled work stops touching app state.

timer = every 1 second {
    print "tick"
}

timer.cancel

Cancelled timers never fire again, leave the schedule, release resources, and don't keep the app alive. UI stays responsive during network work because I/O never blocks the event loop.

6. Networking and JSON

try {
    response = http get "https://example.com"
    print response.status
    print response.text
}
error {
    print error.message
}

Timeouts, DNS failures, and bad URLs become catchable errors. JSON read/write errors include location and context.

7. Errors and diagnostics

Errors carry message, type, file, line, column — and still print as a human-readable message.

Type Error

calculator.vxl:42:15

result = number + name
               ^

Cannot add a number and a string.

vexel debug inspects AST, symbols, modules, UI tree, windows, controls, tasks, timers, and events — and flags controls outside their parent, negative sizes, duplicate ids, and dangling references.

8. Styles, themes, animation

style primary_button {
    background = "blue"
    text_color = "white"
    border_radius = 8
}

button.opacity = 0.5

Priority: default → theme → reusable style → explicit control property. Opacity is per-control; a backend that can't do it must say so, not fake it. Animations (move, fade, size, durations, easing) keep existing 2.x syntax.

9. Projects and builds

vexel project create
vexel run
vexel build
vexel clean

Builds validate in order: parse → semantic analysis → project validation → UI validation → codegen → build. Malformed projects produce clear errors, never backend stack traces. Shutdown is deterministic: stop timers, cancel tasks, close windows, release everything.
