# Vexel 3.0 — Praxis Foundation

**Vexel 3.0.0 introduces Praxis, the Vexel-native UI and application engine.**

Architecture:

```
Vexel Source Code
       ↓
  Vexel Compiler
       ↓
  Vexel Runtime
       ↓
     Praxis
       ↓
Praxis Rendering Layer
       ↓
    OS / GPU
```

You only write Vexel. Backend technologies never leak into `.vxl` sources.
Every snippet below was verified with `vexel check` against the 3.0 compiler.

## Basic UI (unchanged)

```vxl
create a window titled "My App"
button = add a button titled "Click Me"
input = add an input box titled "Your name"
output = add an output box
button.on click {
    output.text = input.text
}
window.show
```

## Layout (deterministic)

Manual positioning is parent-relative with no hidden offsets:

```vxl
create a window titled "Layout"
a = add a button titled "One"
a.x = 30
a.y = 20
a.width = 80
a.height = 30
b = add a button titled "Two"
b.x = 120
b.y = 20
b.width = 80
b.height = 30
window.show
```

Responsive sizes coexist with manual positions:

```vxl
create a window titled "R"
b = add a button titled "B"
set b width to 50 percent
set b height to fill
window.show
```

Containers: `add a panel`, `add a scroll area`, `create a horizontal container`,
`create a vertical container`, `create a grid container`, `create a scroll container`.
Center: `b.center`. Window bounds: `window.width`, `window.min_width`, etc.

Check geometry without running:

```bash
vexel debug --dpi all app.vxl
```

## Widgets

Buttons, text, input/output, checkbox, slider, progress, spinner, dropdown,
list, image, menu, toolbar, tab bar, table, tree, panel, scroll area, form.

New in 3.0 (all real implementations):

```vxl
create a window titled "New"
sw = add a switch titled "Power"
sw.checked = true
rb = add a radio button titled "A"
rb.group = "g"
num = add a numeric input
num.value = 42
sbox = add a search box titled "Search..."
card = add a card titled "Card"
note = add a text titled "Hi" to card
sep = add a separator
bar = add a status bar titled "Ready"
bar.text = "Go"
ctx = add a context menu
item = ctx.add "Hello"
window.show
```

Icons and tooltips (buttons and menu items take icons; every element takes a tooltip):

```vxl
create a window titled "T"
b = add a button titled "Save"
b.icon = "save"
b.tooltip = "Save file"
b.description = "Saves the file"
window.show
```

Available icons: add, check, close, delete, edit, folder, info, open, pause,
play, refresh, save, search, settings, star, warning. Unknown names are a
runtime error listing the available names.

## Dialogs

```vxl
create a window titled "T"
show message "Saved successfully"
show warning "Careful"
show confirmation "Delete this file?"
show input dialog "Enter your name"
ok = confirm "Are you sure?"
typed = prompt "Your name?"
asked = ask "Continue?"
window.show
```

`confirm`/`ask` return boolean. `prompt` returns text ("" means cancelled).
`show confirmation` and `show input dialog` are modal statement forms.

## Notifications

Non-blocking toasts (never block the UI thread):

```vxl
create a window titled "T"
show notification "File saved"
show notification success "Done" for 2 seconds
window.show
```

Kinds: info (default), success, warning, error.

## Animation

Non-blocking, with linear (default) or smooth easing:

```vxl
create a window titled "T"
b = add a button titled "B"
animate b {
    move to x 200
    duration 1 second
}
window.show
```

```vxl
create a window titled "T"
b = add a button titled "B"
animate b {
    move to x 200
    ease smooth
    duration 1 second
}
window.show
```

## Events

```vxl
create a window titled "T"
b = add a button titled "B"
b.on click {
    print event.target
}
b.on mouse move {
    print event.button
}
field = add an input box titled "Type"
field.on key press {
    print key
}
field.on change {
    print event.value
}
window.show
```

Click/focus/blur/resize/move/close expose `event.target`. Mouse events add
`event.x`, `event.y`, `event.button`. Key events expose `key`. Change events
expose `event.value`.

## Keyboard and focus

```vxl
create a window titled "T"
b = add a button titled "B"
b.focus
print b.focused
window.show
```

`focused` is read-only. Tab navigation is handled by the backend.
Shortcuts: `b.shortcut = "Ctrl+S"`.

## Windows

```vxl
create a window titled "Main"
window.width = 800
window.height = 600
win2 = create a window titled "Second"
win2.width = 400
win2.height = 300
btn = add a button titled "Open"
btn.on click {
    win2.show
}
window.show
```

Window methods: show, hide, close, minimize, maximize, restore, focus.
Closing the last open window stops timers and cancels tasks deterministically.

## Accessibility

```vxl
create a window titled "T"
b = add a button titled "Save"
b.description = "Saves the file"
b.tooltip = "Save file"
window.show
```

Every element exposes `focused` (read) and `description`/`tooltip`
(read/write). Names are exposed to assistive tech automatically.

## DPI and scaling

Logical coordinates throughout. Validate without screenshots:

```bash
vexel debug --dpi all app.vxl
```

100/125/150/175/200% scales are computed uniformly. Fractional results are
flagged as blur risks.

## Known limitations (honest)

- UI builds need the .NET 8 SDK; this environment has only the .NET 8
  runtime, so `vexel build`/`vexel run` for UI programs fail with a clear
  toolchain error. `vexel check`/`vexel debug` fully validate UI programs.
- `wait <task>` is console-only; UI programs poll `handle.state` from a timer.
- `vexel test` is console-only.
- Context menus show as popups; toolbar groups are labeled strips.
- Table columns are proportional; no interactive column resizing.
- Toasts are topmost windows, not composited GPU layers (render-command log
  in Praxis is the GPU-ready abstraction foundation).
- `examples/chess.vxl` uses `r` as a variable, which collides with the
  `r from ...` random syntax (pre-existing, unchanged in 3.0).
