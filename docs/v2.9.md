# Vexel 2.9 — What's New

**Vexel 2.2 — Real Applications. Vexel 2.9 — More Language.**

2.9 keeps every 2.2 program working and adds: enums, safer nulls, pattern
matching, terminal sessions, filesystem APIs, CLI arguments, a test
system, a staged `vexel check`, better diagnostics, console tasks with
waiting, fuller HTTP, incremental builds, and UI additions (shortcuts,
toolbar separators/groups, a rendering data table with selection,
DPI debug matrix, layout validation).

Every snippet below was compiled against the 2.9 compiler; runnable
snippets were executed. New items are marked **Available in Vexel 2.9**.

## Enums (Available in Vexel 2.9)

```vxl
enum State {
    idle
    running
    finished
}

state = State.idle
print state
```

Values are newline-separated (commas allowed); at least one value is
required. `State.running` has the static type `enum State` and prints as
`running`. Enums work in conditions, functions, structs, lists and
imports (`public enum` + `game.State` + `game.State.hard`).

```vxl
enum State {
    idle
    running
    finished
}

state = State.running

if state = State.running {
    print "Go!"
}

function isDone s {
    return s = State.finished
}

print isDone State.finished
```

Errors: unknown values name the available ones; assigning another type
is a TypeError; a bare `State` is not a value; duplicate/empty enums and
name clashes with structs/functions fail at compile time. Enums join
with strings (`"state: " + state`).

Limitations: match arms use `State.value` or bare values only when the
subject is that enum; cross-module match arms use local enum names.

## Null safety (Available in Vexel 2.9)

No new syntax. The compiler tracks variables definitely holding `null`
and rejects dangerous uses with `NullSafetyError`:

```vxl-fail
x = null
print x + 1
```

```text
Type: NullSafetyError
Cannot use 'x' here because it holds null. 'x' was assigned null at
line 1. Check it first (if x = null { ... }). Give it a value before
this line to proceed.
```

Checked: arithmetic and string joining with null, field/index reads and
writes through null (`x.name`, `x[0]`, `x.y = 1`), `length of`,
`number of`, `[i] from`, and `make` on null. Comparisons against null
(`if x = null`) always stay allowed, as do `print` and passing null
into functions. Reassignment clears the tracking. Values that *may* be
null at runtime (JSON reads, `any` values) are unchanged — check them
with `if x = null` as before.

## Pattern matching (Available in Vexel 2.9)

```vxl
enum State {
    idle
    running
    finished
}

state = State.running

match state {
    idle {
        print "Waiting"
    }
    State.running {
        print "Running"
    }
    _ {
        print "Other"
    }
}
```

Arms: literals (`1`, `"go"`, `true`), `Enum.value`, bare enum values
when the subject is that enum, `null`, and one trailing `_` default
(which must be last). Duplicate arms, literals that can never match the
subject type, and literal arms on enum subjects are compile errors.
Both backends emit an `==` chain; the subject evaluates once. `match`
works in functions, handlers and tasks.

## Terminal sessions (Available in Vexel 2.9)

```vxl
terminal {
    cd "C:\Projects"
    run "mkdir Test"
    cd "Test"
    run "echo Hello"
}
```

One block is one persistent session: later commands see earlier `cd`
changes. `out = run "cmd"` captures stdout as text instead of showing
it. Non-zero exits, missing directories, and missing executables are
catchable runtime errors naming the cause — never silent. Commands run
through the host shell (`cmd /C` on Windows, `sh -c` elsewhere), which
is an implementation detail: Vexel sees only `cd`/`run`. Only `cd` and
`run` may appear inside the block; bare `cd` outside a block is a
compile error. Each block starts a fresh session at the program's
working directory.

## Filesystem (Available in Vexel 2.9)

```vxl
file write "Hello" to "notes.txt"
file append "!" to "notes.txt"
print file read "notes.txt"
print file exists "notes.txt"
print file size "notes.txt"
file copy "notes.txt" to "backup.txt"
file move "backup.txt" to "final.txt"
file delete "notes.txt"
file delete "final.txt"

dir create "work/shapes"
print dir list "work"
print dir exists "work"
dir copy "work" to "work2"
dir move "work2" to "work3"
dir delete "work"
dir delete "work3"
```

Values written must be text; paths must be strings. `dir list` returns
sorted names. `dir delete` removes recursively. Every failure (missing
files, bad paths) is a catchable runtime error. The classic
`print data/info.txt` read stays as-is.

## CLI arguments (Available in Vexel 2.9)

```vxl
// vexel hello.vxl Zen
name = args[0]
print "Hello " + name
```

`args` is the argument list after the program (length via
`args.length`). The CLI forwards trailing words to the program for both
`vexel file.vxl ...` and `vexel run ...`. Out-of-range access is a
catchable runtime error. A user variable named `args` shadows the
builtin (like `paste`).

## Tests (Available in Vexel 2.9)

```vxl
function add a, b {
    return a + b
}

test "addition" {
    result = add 5, 3
    assert result = 8
}
```

```bash
vexel test math_tests.vxl
```

```text
Vexel Test Runner
✓ addition
✓ division
✓ divide by zero

3 passed
0 failed
```

`assert` needs a boolean; failures report `Assertion failed (file.vxl
line N)`. `vexel test` compiles a runner: module setup runs first, then
each test in order — one failure never stops the suite, and any failure
exits non-zero. Tests share module globals (documented). Test names are
unique per module; tests cannot nest in functions/handlers/tasks and
cannot use `return`. UI programs get a clear error directing testable
logic into console modules. Asserts also work as preconditions in
normal code (both backends).

## vexel check (Available in Vexel 2.9)

```bash
vexel check hello.vxl
vexel check            # project entry point
```

```text
Vexel Check
✓ Parsing (1 file)
✓ Type checking
✓ Modules (1 module)
✓ Code generation
0 errors
0 warnings
```

Every stage runs: parsing, type checking, modules, then backend
validation (`UI validation` for UI programs, `Code generation` for
console). Real warnings are reported: duplicate imports, and static UI
geometry problems (overflow, negative/zero sizes, overlaps, duplicate
ids). Bare `vexel check` resolves the project entry (root walk-up,
`main.vxl`, `src/main.vxl`).

## Diagnostics (Available in Vexel 2.9)

Reassignment errors name the previous type and line plus one safe
suggestion:

```text
Type mismatch: variable 'name' is string but assigned integer.
'name' was previously inferred as string at line 1.

Suggestion:
Use a separate variable for the integer value.
```

Unknown names get a closest-match hint within a tight threshold:

```text
Undefined variable 'naem'. Did you mean 'name'?
```

Caret format is unchanged, so existing tooling keeps matching.

## Tasks (2.9 improvements)

Console programs gain real background tasks (worker threads, read-only
globals snapshot, locked `result` handoff):

```vxl
task calc {
    total = 0
    n = 1
    repeat till n = 6 {
        total = total + n
        n = n + 1
    }
    result = total
}

wait calc
print calc.state
print calc.result
```

`wait <handle>` blocks until `completed`/`failed`/`cancelled`
(console only — UI programs keep polling `handle.state` from a timer;
`wait` on a handle there is a clear backend error). Cancellation stays
cooperative (loop heads, `wait`, in-flight HTTP). New rejections read
clearly: `return` is forbidden in tasks (assign `result`), and
`wait x` on a non-handle is a type error. Task errors arrive as
`handle.error.message`; premature `handle.result` reads fail loudly.

Limitations: snapshots and results cross threads as data (JSON-shaped
values); `result` of exotic values may not round-trip — keep results
to plain data.

## HTTP (2.9 improvements)

```vxl
payload = {
    name = "Zen"
}

response = http get "https://example.com"
created = http post "https://example.com/items", "name=zen"
sent = http put "https://example.com/items/1", payload, { token = "abc" }
gone = http delete "https://example.com/items/1"

http timeout 5
```

One rule: `http METHOD URL [, BODY] [, HEADERS]`. Bodies may be text
or objects/lists (sent as JSON); headers must be objects. `get`/`delete`
take an optional headers object instead of a body. Responses keep
`status`/`text`/`body`/`headers`. Console programs serve `http://`
over plain TCP (no TLS in the std-only backend — `https://` there is a
clear catchable error directing to desktop builds); UI programs keep
full `http(s)` via the shared client, now also cancellable through
tasks. Default timeout is 30s, configurable with `http timeout`.

## Incremental builds (Available in Vexel 2.9)

```bash
vexel build app.vxl     # full backend build, cached by content hash
vexel build app.vxl     # Up to date ... (sources unchanged, build skipped)
vexel clean             # removes executables AND .vexel-cache
```

The key covers the compiler fingerprint plus every transitive source's
bytes, so stale outputs are impossible: edits anywhere (including the
compiler itself) rebuild. `vexel run` reuses the same cache. `vexel
clean` removes `.vexel-cache` alongside executables.

## UI additions (Available in Vexel 2.9)

Shortcuts (buttons, toolbar buttons, menu items):

```vxl
create a window titled "Shortcuts"

save = add a button titled "Save"
save.shortcut = "Ctrl+S"

save.on click {
    print "saved!"
}

window.show
```

Specs look like `"Ctrl+S"`, `"Ctrl+Shift+O"`, `"Alt+F4"`, `"F5"`.
Bad modifiers and missing keys fail at compile time; unknown keys fail
at runtime naming the key. Firing raises the control's click, so the
same handlers run.

Toolbar separators and groups:

```vxl
create a window titled "Toolbar"

bar = add a toolbar
save = bar.add a button titled "Save"
bar.add separator
grp = bar.add group "Edit"
cut = grp.add a button titled "Cut"

window.show
```

Groups are labeled strips that take buttons exactly like toolbars.

Data tables render rows and support selection:

```vxl
create a window titled "Table"

grid = add a table
grid.add column "Name"
grid.add row ["Zen", 25]
grid.selected = 0
print grid.selected

grid.on change {
    print event.value
}

window.show
```

`selected` is the row index (`-1` = none), readable and settable;
programmatic sets fire `change` with the index. `grid.clear` empties
rows. Tables are built from core controls, so they render with the
bundled theme on every backend.

Layout validation and DPI:

```bash
vexel debug --dpi all app.vxl
```

Reports device pixels per scale (100/125/150/175/200) with
fractional-pixel (blur-risk) flags, plus new static warnings for
overlapping siblings and zero-area controls. Manual `x/y/width/height`
behavior is unchanged and deterministic.

## Projects (2.9 improvements)

Commands resolve the project root by walking up to `vexel.project`,
so `vexel run/build/check/test` work from subdirectories. Entry
resolution: `vexel.project` main, then `main.vxl`, then
`src/main.vxl`. Bare `vexel check` and `vexel test` target the entry.

## Compatibility

All valid 2.2 programs compile and run unchanged, except these
intentional narrowings (each with a clear error):

- `task` in console programs now runs on workers (was: needs-a-window
  error); `return` inside any task is now rejected.
- `wait x` on a non-seconds value now means task-wait (was: missing-unit
  error); UI programs get guidance to poll instead.
- `assert ...` statements and `test "..." {` blocks are now test
  syntax (were: calls to user functions of those names, if any).
- `run "..."` / `cd` shapes are terminal syntax (same caveat).
- `file ...` / `dir ...` shapes are filesystem syntax (same caveat).
- Data tables render (previously invisible) and programmatic
  `table.selected` fires `change`.
- `print` of enum values and `"text" + enum` now work (were: type
  errors).
- `vexel check` output is staged (exit codes and failure text
  unchanged); `vexel debug` accepts `--dpi`.
