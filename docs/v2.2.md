# Vexel 2.2 — Real Applications

**Vexel 2.0 — UI. Vexel 2.1 — Runtime. Vexel 2.2 — Real Applications.**

2.2 keeps every 2.0/2.1 program working and moves the UI runtime to
Avalonia (.NET 8 + Avalonia 11): multiple windows, cancellable
timers, background tasks, real HTTP, per-control opacity,
animations, processes, and a live inspector.

## Backends (2.2.1: one backend)

- **Avalonia is the UI backend.** Plain `vexel build` / `vexel run`
  compile UI programs to native Avalonia apps (single exe plus
  Avalonia native DLLs) using the .NET 8 SDK + Avalonia 11.3.x from
  NuGet. `--avalonia` is accepted and ignored.
- WinForms (`compiler/codegen/codegen_cs.js`, `runtime/ui/VexUI.cs`,
  `VexCore.cs`, csc paths) is deleted. No WinForms code, references,
  or fallbacks remain.
- Console programs still use Rust (`rustc`), unchanged.

No Avalonia names ever appear in `.vxl` sources. Unsupported shapes
fail as `BackendError` naming the feature — never silent, never fake.

## What shipped (all proven live, not just compiled)

- **Coordinates**: absolute client-area pixels, zero-padding root,
  single DPI conversion, parent-relative container children.
  `vexel debug` prints static geometry + overflow/negative/dup-id
  warnings.
- **Windows**: unlimited named windows (`main = create a window
  titled "Main"`), per-window size/controls/events/lifecycle,
  `show/hide/close/minimize/maximize/restore`, `resize/move/close/
  focus/blur/key` events. Closing one window never kills the others;
  the app exits with the last.
- **Multi-module programs**: imports work (`P_`-prefixed statics,
  per-module inits in dependency order, cross-module calls).
  Proven on the calculator (`calculator_app.vxl` + `calc/logic.vxl`):
  7+8=15 computed live through the import.
- **Timers**: bare + handle (`ticker = every 1 second {...}`,
  `ticker.cancel`) on the UI thread; shutdown stops them all.
- **Tasks**: `task name {...}` on worker threads with
  `pending/running/completed/failed/cancelled` states,
  `handle.result` (locked handoff), cooperative `handle.cancel`
  (loop heads, `wait`, HTTP tokens), `handle.error.message`.
  Bodies are isolated scopes; UI touches fail with guidance to
  poll from a timer.
- **HTTP**: `http get "url"` gives `status/text/body/headers`, 30s
  default timeout, all faults mapped to catchable Vexel errors.
- **Processes**: `p = process "exe", "args"...` with
  `p.running/exit/stdout/stderr` polling + `p.kill`. Proven live
  (exit 0, output captured, kill stops ping).
- **Opacity + animation**: real per-control `opacity` (0-1, checked
  twice) and 60fps non-blocking `animate` (move/size/fade).
- **Widgets**: button, text, input, output, checkbox, slider,
  progress, dropdown, listbox, image, spinner, menu, tab bar, tree,
  toolbar (strip of real buttons), table (real DataGrid);
  explicit containers (panel, horizontal, vertical, grid, scroll)
  with re-parenting (`add X to Y`).
- **Responsive anchoring**: `b.anchor = "right"`,
  `"left right"`, `"bottom right"` — edge distances track parent
  resizes exactly (measured live).
- **Language in handlers**: variables, arithmetic, `if`, loops,
  `print`, JSON, `try`/`error`, `wait`, `make`, `number of`,
  indexing, random, lists, user functions, `ask`.
- **Dialogs/pickers/clipboard**: truly modal message/warning/ask
  (nested loop), file/folder/color pickers with
  cancel-vs-error distinction, clipboard copy/paste roundtrip.
- **Live inspector**: `VEXEL_AX_SNAPSHOT=<path>` writes live
  windows/controls/bounds/opacity + timer/task states on every
  transition. Verified against real clicks.
- **Errors**: `error.message/type/file/line/column`, printable as
  the message; network faults name URL + reason.

## Verification method

Every claim above was proven by running real exes and observing
real effects (window titles, files written by handlers, process
exit, screenshot pixels): clicks/keys via OS input injection,
WM_CLOSE dismissal, JSON-observed state, PrintWindow-free screen
capture. Suites: 43/43 console + 70/70 UI green (see final report).
